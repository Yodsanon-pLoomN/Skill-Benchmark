# Checklist — explain-03

## ความถูกต้อง/ความครบถ้วน

1. คำตอบอธิบายว่า `Include(r => r.Bookings)` ทำให้ query ดึงข้อมูล Booking ของแต่ละ Room มาพร้อมกันในคำสั่งเดียว (join) แทนที่จะต้อง query แยกทีละห้อง (หลีกเลี่ยง N+1)
2. คำตอบระบุว่าถ้าไม่มี `Include`, `room.Bookings` ของแต่ละ Room ที่ดึงมาจะเป็น collection ว่างเปล่า (ไม่ error, ไม่ lazy-load อัตโนมัติ) ทำให้ทุกห้องรายงานว่ามี 0 booking และ 0 ชั่วโมงอย่างผิดพลาด
3. คำตอบอธิบายว่าหลังจาก fetch แล้ว มีการคำนวณ `RoomUsageSummary` ต่อห้องใน memory ด้วย `.Select(...)` แล้วเรียงด้วย `OrderByDescending` ตาม `TotalBookedHours` ก่อน return
4. คำตอบอธิบายว่าเหตุผลที่กรองด้วย `Status == "CONFIRMED"` คือ booking ที่ CANCELLED ยังมีอยู่ในฐานข้อมูล (ไม่ถูกลบ) แต่ไม่ควรถูกนับเป็นการใช้งานห้องจริง
5. คำตอบระบุว่าถ้าไม่มีการกรอง CONFIRMED ห้อง Beta จะถูกรายงานผิดว่ามี 1 booking และ 2 ชั่วโมง (จาก `seed-3` ที่จริงแล้วถูกยกเลิก)
6. คำตอบสรุปชัดเจนว่า `GetRoomUsageAsync()` สำหรับห้อง Beta ในปัจจุบัน "ไม่ throw" (ไม่ error, ไม่คืนค่า null)
7. คำตอบอธิบายว่า confirmed list ของ Beta ว่างเปล่า (เพราะ `seed-3` เป็น CANCELLED) และ `.Sum()` บน list ว่างคืนค่า 0 อย่างปลอดภัย (ต่างจาก `.Max()`/`.Average()`/`.First()` ที่จะ throw บน list ว่าง)
8. คำตอบระบุว่าผลลัพธ์สำหรับ Beta เป็นแถวข้อมูลปกติที่มีค่าเป็น 0 ทั้งหมด (count=0, total hours=0) รวมอยู่ใน list ผลลัพธ์เหมือนห้องอื่น

## คุณภาพ

9. คำตอบเรียงลำดับตามคำถามทั้ง 3 ข้อ และระบุข้อสรุปของข้อ 3 ("ไม่ throw") ไว้อย่างชัดเจนตั้งแต่ต้นคำตอบ ไม่ใช่ฝังกลางย่อหน้า
10. คำตอบใช้ศัพท์ทางเทคนิคถูกต้องสม่ำเสมอ (`Include`, LINQ, `Sum` vs `Max`)
11. ไฟล์ในโปรเจกต์ไม่ถูกแก้ไข/สร้างใหม่ (ตรงตามคำสั่ง "do not change any files")
