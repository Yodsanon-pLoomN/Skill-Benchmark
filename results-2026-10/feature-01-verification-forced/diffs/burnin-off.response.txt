**What I added** (in `workspace/sample-project-reports-api`):
- `Controllers/BookingsController.cs` exposes `PATCH /bookings/{id}/extend` with body `{ "newEndsAt": "<ISO 8601>" }`. On success it returns 200 with the updated booking.
- `Services/BookingExtensionService.cs` holds the four rules and saves the new `EndsAt`.
- `Program.cs` registers the new service.

**Error responses** (all returned as ProblemDetails):

| Case | Status |
|---|---|
| Booking not found | 404 |
| Booking is not `CONFIRMED` (cancelled) | 409 |
| Extended range overlaps another `CONFIRMED` booking in the same room | 409 |
| `newEndsAt` is not strictly after the current `EndsAt` | 400 |
| Total duration from `StartsAt` to `newEndsAt` exceeds 8 hours | 400 |
| `newEndsAt` missing | 400 |

**Two choices you may want to check:**
- The overlap test is the half-open form from your spec: `a.StartsAt < b.EndsAt && a.EndsAt > b.StartsAt`. A booking that ends exactly when another starts is allowed. It runs in memory, because SQLite stores datetimes as text.
- SQLite returns datetimes with an unspecified kind. The service treats stored values as UTC and converts the request's `newEndsAt` to UTC before comparing, so offsets like `+07:00` compare correctly.
