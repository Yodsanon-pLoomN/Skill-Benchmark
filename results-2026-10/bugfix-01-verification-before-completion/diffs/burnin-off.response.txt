I found one bug behind each report and fixed both. All 13 existing tests pass. I didn't add new tests for these two cases.

**Report 1 (back-to-back meetings rejected).** `overlaps()` in `src/domain/booking.ts` used `<=` and `>=`, which treats bookings that only touch at 11:00 as overlapping. DOMAIN.md defines the interval as half-open, so I changed it to strict `<` and `>`.

**Report 2 (cancelled booking still blocks the slot).** `findBookingsForDay()` in `src/repositories/bookingRepository.ts` didn't filter by status. Its comment said it excluded cancelled bookings, but the query never did. Cancelled bookings were therefore counted in both the conflict check and the availability view. I added `status: "CONFIRMED"` to the query, which follows rule 2 for both.
